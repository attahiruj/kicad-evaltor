# Architecture

How a design file becomes a pass/fail verdict. The pipeline is deliberately
layered so that each stage can be tested on its own with no KiCad installed.

```
.kicad_sch
    │
    ▼
sexpr.py            generic s-expression reader
    │
    ▼
schematic_file.py   FileSchematic: symbols, fields, wires, labels, lib_symbols
    │
    ▼
schematic_items.py  SchematicScene: components, text, wires with real geometry
    │
    ├──► font_metrics.py    glyph extents, from calibrated stroke-font data
    ├──► text_placement.py  where each kind of text is drawn, also calibrated
    │
    ▼
collisions.py       pairwise overlap over axis-aligned boxes
    │
    ▼
checks/             one module per check, registered by dotted id
    │
    ▼
core/runner.py      TestReport
```

## Layers

### `sexpr.py`

A small s-expression reader. No knowledge of KiCad beyond the `(head value ...)`
shape. Everything above it works with plain nested lists and strings.

### `schematic_file.py`

Parses `.kicad_sch` into `FileSchematic`. This layer is a faithful reading of
the file and makes no geometric claims: it reports the `(at x y angle)` a field
records and whether `(hide yes)` is present, but does not decide what that means
for rendering.

It reads exactly one file. A KiCad schematic is a tree of files, and walking
into the subsheets is `hierarchy.py`'s job — which is what keeps "one file, one
coordinate space, one paper size" true here.

That separation is the point. Every judgement call about how KiCad actually
draws something lives in one place, the next layer, where it can be compared
against a real rendering.

`lib_symbols` is read as well, so a symbol's body and pins can be recovered by
looking up each placed symbol's `lib_id`.

### `sheets.py`

Reads one file's `(sheet ...)` and `(pin ...)` blocks into `Sheet` and
`SheetPin`. A `Sheet` carries its `Sheetfile`, the candidate paths that filename
could resolve to, the pins its symbol declares, and KiCad's uuid instance path.
It is a faithful reading, like `FileSchematic`, and resolves nothing on its own.

### `hierarchy.py`

Walks a design from its root file. `SchematicTree` loads each linked file once,
memoises one scene per sheet, and reports what it could not load as a
`SheetProblem` rather than raising. `tree_for()` memoises the tree per parsed
root in a `WeakKeyDictionary`, so a discarded context takes its tree with it and
seven layout checks over one design parse it once.

Three decisions here are load-bearing:

- **Cycles are keyed on the path, not on the files seen.** KiCad legitimately
  instantiates one file under several sheet symbols. Only a path that reaches one
  of its own ancestors is a cycle, so the walk carries the chain rather than a
  visited set.
- **A `Sheetfile` resolves against the project folder first**, then the folder of
  the file holding the link. This is what KiCad does, and it is why a link of
  `../shared/shared.kicad_sch` works from a subdirectory.
- **Sheets are walked in the order they are drawn.** Children are pushed in
  reverse so they pop in declaration order, and their problems are recorded on
  the way past in that order, so both lists read top-down like the design does.

`select_sheets()` and `select_targets()` resolve the `sheet` parameter and
default to the whole tree. See the README for why the default is not the root.

### `font_metrics.py`

Text geometry, from `_stroke_font_data.json`. That file is generated by
`tools/calibrate_stroke_font.py` from an actual KiCad rendering, so text metrics
do not depend on KiCad being installed.

It knows the font, not the sheet: how wide each glyph is and where its ink sits
relative to the pen, for text read left to right around an anchor. `left`
justification starts the text at the anchor, `right` ends it there, and the
default centres it. Where each kind of item puts that text is
`text_placement.py`'s job.

### `text_placement.py`

Where KiCad actually draws each kind of text, from `_text_placement_data.json`,
which `tools/calibrate_text_placement.py` measures from kicad-cli the same way
the font is measured. Run it after the font calibration. KiCad lifts a net label
off its wire, starts a global label's text past its flag, and places text by a
pen width that is not always the one it draws with; none of that is published.
The table holds a correction for every kind, label shape, orientation and
justification, each linear in size, pen and text width, and the tool checks it
against probe sets it was not fitted on. It also gives the outline of global and
hierarchical labels.

A text item's box is its drawn ink, stroke included, and a label's flag is kept
as a separate piece so the empty corners around both never collide. Rotation
follows KiCad:

- **Sheet text and labels** are drawn at their angle modulo 180: the angle says
  across or up the sheet, and the justification which way from the anchor.
- **Symbol fields** are justified in their own frame and carried through the
  field angle and the symbol's rotation and mirror, but the letters are drawn
  at the field's own angle, swapped between flat and vertical when the symbol
  stands on its side, and never mirrored. A field at 180 is upside down.

A full run against kicad-cli, every symbol rotation and mirror, every field
angle and justification and every label kind and shape at every angle, lands
within a micron. If a layout finding cannot be reproduced in KiCad's own
viewer, suspect these two modules and re-run both calibrations.

### `geometry.py`

`Placement` and `BBox`. All rotation goes through `Placement.apply_box`; do not
open-code trigonometry elsewhere. The transform is

```
global = anchor + (x·cosθ − y·sinθ,  x·sinθ + y·cosθ)
```

with y increasing downward, matching the file. A symbol's `(mirror x)` or
`(mirror y)` is applied on the sheet *after* its rotation; at 90 and 270 degrees
that order decides which way the body faces.

### `schematic_items.py`

Turns a `FileSchematic` into a `SchematicScene` of components, text items,
wires, junctions and labels, each with a real bounding box. This is where
rendering judgements are applied, and where hidden items are dropped: anything
marked `(hide yes)` is skipped, and a power symbol's `Value` is skipped because
KiCad draws that name in the symbol's artwork rather than as a field.

A symbol keeps the box of each graphic it is drawn from, as `body_parts`, beside
the box around its whole body. The overlap checks measure those pieces and each
pin line, never the enclosing box: a symbol is mostly empty space, and an LED's
arrows or a connector's spread of pins would otherwise make text placed in that
space look as if it touched the drawing.

Hidden is not one spelling. KiCad puts the flag beside a symbol field and a
symbol pin, but inside the `(effects ...)` block for everything built on a
TEXT_EFFECTS block — `text`, the three label kinds, a sheet pin. `sexpr.is_hidden`
looks in both places so no caller has to know which kind of node it holds, and it
reads the flag's value rather than its presence, so an explicit `(hide no)` is
not mistaken for hidden.

One file in, one scene out. A sheet is its own coordinate space with its own
paper size, so a scene must never be built from more than one file.

### `collisions.py`

Pairwise overlap over axis-aligned boxes. Clearance is the minimum axis gap;
touching bounds count as `0.0`, not as an overlap.

### `checks/`

One module per check. A check declares a stable dotted `id`, a name, a
description and a `CheckParams` dataclass, and is registered with `@register`.
Ids are a public interface; never renumber one.

`schematic/overlaps.py` backs the layout checks, which differ only in which item
kinds they pair up. Each takes an optional `sheet` selector and runs once per
selected sheet through `_over_sheets`, totalling the findings and qualifying
labels with the sheet name. `schematic/sheets.py` backs the four `sch.sheet.*`
checks. `pcb/` is not implemented — see below.

### `core/`

`DesignContext` owns the design, finds `kicad-cli`, and runs it as a subprocess
for netlist, ERC and DRC. `TestRunner` takes a list of checks and produces a
`TestReport`.

`kicad-cli` is located on `PATH` first, then in the standard install locations,
since KiCad does not add itself to `PATH` on Windows.

Its JSON reports are not the same shape, and the difference matters. ERC is per
sheet: the top level carries only metadata, the violations live in
`sheets[*].violations`, and there is no top-level `violations` key at all. DRC
stays as one flat top-level list. A parser that reads only the top level finds
nothing in an ERC report and reports a schematic with errors on it as clean, so
`utils/kicad_cli.py` reads the sheet-nested shape and falls back to the flat one
that KiCad 8 and 9 wrote. Both reports spell a violation's text `description` and
keep positions in `items[*].pos`; there is no `message` and no `at`.
`violation_details` projects those into one stable spelling for both checks.

The report shape is read off a real `kicad-cli` invocation in `test_integration.py`,
against a fixture that genuinely has errors on it, rather than from the docs — the
demo design is clean and so cannot show a parser finding anything.

`DesignContext.schematic` is the root file only. `sheet_tree()` returns the whole
design and `sheet_symbols()` flattens its symbols, each tagged with the sheet it
came from; a component-level question is asked through the latter. Geometry is
never asked that way, because two sheets' coordinates are two coordinate spaces.

## Boundaries worth respecting

- **`kicad-cli` is only for netlist, ERC and DRC.** KiCad 10 removed
  `kicad-cli api-server`, so nothing depends on the IPC API. Symbols, values,
  fields and text geometry all come from parsing the file.
- **No global or project KiCad configuration is ever modified.** Checks read;
  they do not rewrite project settings.
- **`report_workspace` changes process-wide CWD** and is not thread-safe. Do not
  call it from concurrent check execution.
- **One sheet is one coordinate space.** Two files' geometry is never compared,
  and a `SchematicScene` is never built from more than one file. Aggregation
  across sheets is done by iterating sheets, not by merging their items.
- **A sheet that cannot be read is reported, never raised.** `sch.sheet.file_missing`
  owns that finding; every other check carries on with what did load.

## Not implemented

`checks/pcb/` registers six checks (`pcb.footprint.exists`,
`pcb.footprint.overlap`, `pcb.trace.width`, `pcb.trace.length`,
`pcb.power.pour`, `pcb.drc`) plus `project.schematic_pcb_consistency`. They are
scaffolding: they appear in the registry and construct, but they read a
`FootprintInstance` that `models/` does not define, so they cannot run. They are
excluded from the mypy gate. Board work is a separate effort.
